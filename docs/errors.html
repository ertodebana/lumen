Chapter 9

Errors

When Lumen cannot continue, it says what went wrong and on which line. There are two kinds of error, and they happen at different times.

Reading an error

Errors are written to standard error, and the process exits with code 1.

Syntax errors

A syntax error means the text is not a valid program. The whole file is checked before anything runs, so a syntax error on the last line prevents the first line from running.

MessageCause
expected expression, found ...A value was needed and something else was there, such as after let x = or a trailing operator.
expected '{' / '}' / ')'A bracket is missing. Missing closers are reported where the parser gave up, often the end of the file.
expected variable namelet was not followed by a name, or the name is a keyword.
expected parameter nameSomething other than a name appeared in a parameter list.
expected newline or ';' after statementTwo statements share a line without a ; between them.
invalid assignment targetThe left of = is not a variable name, as in a + b = 3.
'return' outside of a functionreturn at the top level of a program.
duplicate parameter 'x'Two parameters of one function share a name.
unterminated stringA string's closing quote is missing. The line is where the string began.
invalid escape '\q'A backslash followed by anything other than n, t, " or \.
unexpected character '@'A character that is not part of the language, outside a string or comment.

Runtime errors

A runtime error happens while the program is running. Everything before the failing line has already taken effect, and its output has already been printed.

MessageCause
undefined variable 'x'Reading a name that is not declared in any enclosing scope.
cannot assign to undefined variable 'x'Assigning without a prior let.
unsupported operands for '-': string and numberAn operator was given types it does not accept. Both types are named.
operand of unary '-' must be a number, got stringNegating something that is not a number.
division by zero / modulo by zeroThe right-hand side of / or % was zero.
can only call functions, not stringCall parentheses after a value that is not a function.
<fn f> expects 2 argument(s), got 1The number of arguments does not match the number of parameters.
len() expects a string, got numberA built-in was given the wrong type.
stack overflowMore than 10,000 nested calls, almost always a recursion with no stopping case.

Which line is reported

The line is that of the operator, the opening parenthesis of the call, or the variable name involved. When the error is inside a function, it is the line inside the function, not the line that called it.

Working without exceptions

Lumen has no way to catch an error: a runtime error ends the program. Check before you act, and return nil or a message when a function cannot do its job.
